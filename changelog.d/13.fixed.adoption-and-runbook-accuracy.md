- **Adoption guide and smoke runbook now match how the reusable workflow and a PAT actually behave** (#13): `docs/adoption/ronda-review-adoption.md`'s caller snippet now declares its own `permissions: { contents: read, pull-requests: write, checks: write }` — a called reusable workflow can only narrow the caller's `GITHUB_TOKEN`, never widen it, so without this block a repository with GitHub's default read-only workflow token failed at startup with zero jobs, no logs, and no annotations reachable from the REST API. The guide also documents the private-repo prerequisite (`Settings → Actions → General → Access`) for adopters running a private fork or instance. `docs/testing/ronda/ronda-v0-github-review.smoke-test.md` now documents the exact `403 You must authenticate via a GitHub App` a personal access token receives from `POST .../check-runs`, and rewrites steps 6, 7, and 9 to assert on Ronda's structured `pass_failed`/log events instead of a check run the local path cannot produce; the corresponding check-run outcomes are covered live by steps 1, 4, and 5. Step 9 now also documents the GitHub-phase timeout path added by #11 (`GithubClientError`, `reason: "timed_out"`) alongside the existing model-phase timeout. Step 10 now runs a second local `npm run review` invocation for the new head SHA and asserts on the log line and the (locally verifiable) absence of a check run for the superseded commit, instead of a check run on the new head SHA that a personal access token can never produce without a follow-up pass; that half is confirmed live by the Actions path instead.
