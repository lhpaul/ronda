- **Repository context no longer requests built-ins, globals and external imports** (#153): candidate identification now skips global and default-library symbols, imports whose specifier is not relative (`node:*`, package names, `paths` aliases), and member accesses whose base is proven not to be repository code (a literal, a primitive-typed value, or something derived only from external imports and lib globals). Provenance the tracer does not model keeps its candidate. These were requested, always dropped as `ambiguous_resolution`, and made a pass with nothing in the repository to resolve report `Repository context unavailable` while spending most of the 12-candidate budget. Such a pass now reports `nothing_to_resolve`, and the check-run summary carries a `Non-repository references skipped` count (a new required `nonRepositoryReferencesSkipped` field on the repository-context record). On PR #145 at `e7e356e` identification goes from 10 requested candidates to 0 (evidence: `docs/testing/ronda/repository-context-noise-evidence-153.md`).
