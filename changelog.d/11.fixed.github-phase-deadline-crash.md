- **Classify a GitHub-phase deadline expiry instead of crashing** (#11): a
  pass deadline that expired during a GitHub API call (rather than the model
  call) previously escaped as an uncaught `AbortError`, with no `pass_failed`
  event, no `timed_out` reason, and no check run published. GitHub calls now
  map an abort to a typed `GithubClientError` at the client boundary (mirroring
  the existing model-client abort mapping), the pass's failure classifier
  recognizes it, and a single failure path now covers the whole GitHub phase —
  including the very first pull-request read. When the triggering
  `pull_request` webhook carried a head SHA, a failure that occurs before any
  API read succeeds now still publishes a `Review failed` check run against
  that commit; when no SHA is known at all (a manual `/ronda review` trigger
  with no readable pull request), the pass logs the classified failure instead
  of crashing. A GitHub check-run lookup failure caused by the same deadline
  now fails fast instead of silently continuing on an already-exhausted
  budget.
